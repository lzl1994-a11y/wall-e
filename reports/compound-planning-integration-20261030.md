# 复合任务接入修复与验证

## 修复边界

本轮处理 LangGraph 执行之前的路由遗漏、单动作校验误伤，以及真实模型候选失败后的受限纠错。保留现有 BT、搜索执行器、硬件所有者和语音模式配置。

- `task_routing.select_task_route` 是请求准备、工具提案审核、原生条件工具和 JSON 条件兜底的共享外层判断。独立前置步骤与条件不能再被单动作条件计划截断。
- 单独停止跟随仍走即时入口；复合请求和条件停止不会被这个快捷入口提前执行。
- 有序步骤的依据回到原文完整分句检查。模型截掉“不要”不能获得许可；引用整句时，可恢复到对应的原文连续片段，并把该依据交给 BT 再次授权。
- 计划级检查保留顺序、已知明确动作覆盖、照片保存要求、禁止项和条件分支。“不要拍照”只约束对应观察的保存，不否决低头、挥手和视觉分析。
- 混合任务的找到后动作仍由原生搜索的 `on_found_actions` 执行。没有找到、无法确定时不会把这些动作改成无条件动作。额外条件无法表达时拒绝整份计划，避免先做前半段。

## LangGraph 的实际职责

新增的小型 `OrderedTaskPlanningWorkflow` 使用现有 LangGraph：

```text
提出完整候选 → 原文与完整计划校验 → 合格后返回执行计划
                         ↓ 不合格
              反馈具体错误，最多修正一次 → 再次完整校验
```

每轮最多两个候选。正常候选只请求一次模型；已经给出的有效候选不额外请求。取消或模型调用异常终止新增规划流程；SDK 原有网络重试配置保持原样。图中不执行硬件，语义纠错也不重试已经完成的物理动作。

## 验证

- 本地 `tests/` 完整套件：1401 passed、8 skipped、1 deselected。
- 最后提示词／依据错误说明调整后的相关回归：80 passed。
- 独立 Git 暂存快照的编排、BT、工具与边界回归：238 passed，确认不依赖工作区中其他未提交改动。
- 使用运行端当前配置进行真实模型规划：最终一轮 18/18 passed，详见 `ordered-dialog-planning-20261030.json`。测试不加载 ROS 或硬件执行器。
- 测试从原话穿过真实请求准备、计划审核、节点编排、现有条件图及搜索计划编译。模型输出、相机、ROS 传输和原生树所有者由夹具模拟，因此这些执行链路测试不等于真机机械动作验证。
- 覆盖同义的“找到后／如果找到就”、停止音乐后观察、局部禁拍照、无标点 ASR、禁止动作与宽依据、找到／未找到／不确定、两次无效候选、取消与调用异常。

真实模型首次扩展测试曾为 15/17，后续发现宽引用及以禁止项代替观察依据的波动；本轮修复保留了拒绝机制，再补限次纠错及明确依据规则。最终一轮通过不表示任意自然语言都能百分之百规划正确。

排除项为已有旧断言 `test_remote_gateway_uses_pyav_resampler_before_ndarray_conversion`，不是本轮新增排除。配置快照只在本机临时目录用于规划测试，结束后删除，不写入 Git。

## 能力范围

当前混合计划支持有界动作、观察、保存与搜索找到后的动作。一般性的任意嵌套条件、额外物体属性条件和并行任务没有在本轮扩展；对识别出不能表达的条件组合拒绝或澄清，不把本轮测试视为任意自然语言的正确性证明。纯单次条件任务继续复用原 LangGraph 工作流。
